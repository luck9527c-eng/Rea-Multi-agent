# 规格验收矩阵

> 状态：以下是插件实现时的验收要求，尚未执行插件或真实 DSH 验收。Schema 与岗位目录的静态验证单独记录，不冒充运行流程通过。

L1 = 工具处理器与团队/文件/项目管理接缝的故障注入；L2 = 临时分析仓库中的真实项目 skill CLI；L3 = 真实 DSH 团队会话。多层场景分别执行，替身不能代替真实 seal 或团队行为。

A37–A44 中的工具发现、发布和提醒由 skill 工作流承担；L1 只验证插件正确消费或拒绝，不要求编排插件实现扫描/渲染器。涉及 skill 工作流的 L2 场景可由 agent 配合文件操作与真实 CLI 演练；专用辅助脚本如新增则在 skill 内验证。

## 规格静态验证

对工具 Schema 执行 Draft 2020-12 元校验，用合法/非法输入输出检查：默认只读 inspect、bind/takeover 必填条件、拒绝不支持的清单刷新 action/返回数据、缺派发字段、非法角色字段/旧 context、收口身份和 review、成功/失败信封、三工具成功 data。工具清单示例还需检查四层未知未冒充验证成功、MD 的源哈希与快照字节一致。能力映射使用工具目录里的完整工具名，不能将 fs/search/jobs/web 能力族或插件 ID 当作已注册工具；组合要求不可被单个读工具满足。

对岗位目录检查：ID 唯一；模板引用存在且不含 disabled；required 族可解析；组合能力无环；精确别名无通配符；mixed 的 game+webapp 并集含各自专岗且不重复。静态检查只证明规格数据自洽，不替代 L1/L2/L3。

运行证据按编号保存输入、原始输出、状态、产物哈希和失败阶段。L3 使用独立临时会话与非敏感测试目标。尚未实现的 case 标待验收，不填占位“通过”。
